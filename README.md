# github.com/satorunooshie/e2e/v2
[![Go Reference](https://pkg.go.dev/badge/github.com/satorunooshie/e2e/v2.svg)](https://pkg.go.dev/github.com/satorunooshie/e2e/v2)

A golden scenario helper for HTTP and gRPC tests. HTTP tests run against
`httptest.NewTestServer`'s in-memory network, and gRPC tests run against an
in-process `bufconn` server, so tests do not need network ports.

gRPC support is published as a separate module so HTTP users do not take a
gRPC/protobuf dependency.

```sh
go get github.com/satorunooshie/e2e/v2
go get github.com/satorunooshie/e2e/grpc/v2
```

## Usage

Once a golden file is generated by `go test -e2e.golden`, e2e compares the HTTP
status code and response dump with the golden file.

```go
func TestUserScenario(t *testing.T) {
    runner := e2e.NewRunner(t, newRouter(), e2e.WithClientTimeout(3 * time.Second))

    var created struct{ ID int }

    t.Run("1 create user", func(t *testing.T) {
        r := e2e.NewRequest(http.MethodPost, "/v1/user", e2e.JSONBody(t, map[string]any{
            "name": "JoJo",
        }), e2e.WithHeader("X-Request-ID", "req-1"))

        runner.RunTest(t, r, http.StatusCreated,
            e2e.CaptureResponse(&created),
            e2e.ModifyJSON(e2e.Fields{
                "created_time": e2e.Verify(UnixTime).ReplaceWith(1677136520),
                "upload_url":   URLValueModifier(e2e.Verify(URL)).MaskQueryExceptKeys("region"),
            }),
            e2e.PrettyJSON,
        )
    })

    t.Run("2 get user", func(t *testing.T) {
        r := e2e.NewRequest(http.MethodGet, "/v1/user/"+strconv.Itoa(created.ID), nil)
        runner.RunTest(t, r, http.StatusOK, e2e.PrettyJSON)
    })
}
```

Run tests with `-e2e.golden` to generate or update golden files.

```sh
go test -v ./... -e2e.golden
```

Then run tests without `-e2e.golden` to compare responses.

```sh
go test -v ./...
```

Use `-e2e.dump` to log the raw response while debugging.

Use `WithGoldenDir` when a package needs separate fixture directories, such as
`e2e.WithGoldenDir("testdata/http")` or
`e2egrpc.WithGoldenDir("testdata/grpc")`.

## JSON normalization

Use `ModifyJSON` with `Fields` to replace nondeterministic response values.
The library intentionally keeps validators minimal; define app-specific checks
with `Verify`. Use `Format` when the helper needs to return a normalized
value for golden comparison.

```go
func UnixTime(t *testing.T, value json.Number) {
    t.Helper()
    if _, err := value.Int64(); err != nil {
        t.Fatalf("JSON value is not a valid Unix timestamp: %v", value)
    }
}

func URL(t *testing.T, value string) {
    t.Helper()
    if _, err := url.ParseRequestURI(value); err != nil {
        t.Fatalf("JSON value is not a valid URL: %q", value)
    }
}

runner.RunTest(t, r, http.StatusCreated, e2e.ModifyJSON(e2e.Fields{
    "created_time": e2e.Verify(UnixTime).ReplaceWith(1677136520),
    "upload_url":   URLValueModifier(e2e.Verify(URL)).MaskQueryExceptKeys("region"),
}), e2e.PrettyJSON)
```

For more detail, see the
[HTTP example](https://github.com/satorunooshie/e2e/blob/main/example/main_test.go)
and its
[app-side JSON modifiers](https://github.com/satorunooshie/e2e/blob/main/example/e2e_helper_test.go).

## gRPC

Use the gRPC helper from the separate module.

```go
import e2egrpc "github.com/satorunooshie/e2e/grpc/v2"

runner := e2egrpc.NewRunner(t, newServer(),
    e2egrpc.UseJSONNames(),
    e2egrpc.WithUnaryTimeout(3 * time.Second),
)
client := pb.NewExampleServiceClient(runner.Conn())

runner.RunUnary(t,
    pb.ExampleService_Get_FullMethodName,
    &pb.GetRequest{UserId: 1},
    codes.OK,
    client.Get,
    e2egrpc.ModifyResponse(e2egrpc.Fields{
        "createdAt": e2egrpc.Verify(UnixTime).ReplaceWith(int64(1677136520)),
        "uploadUrl": URLValueModifier(e2egrpc.Verify(URL)).MaskQueryExceptKeys("region"),
    }),
)
```

For runnable setups with in-process server wiring, metadata, trailers, status
assertions, `UseJSONNames`, and response normalization, see the
[gRPC example](https://github.com/satorunooshie/e2e/blob/main/grpc/example/main_test.go).
Decoded status details are rendered under `status.details`; the transport-level
`grpc-status-details-bin` trailer is omitted from the golden output. Other
`*-bin` metadata values are base64-encoded.
